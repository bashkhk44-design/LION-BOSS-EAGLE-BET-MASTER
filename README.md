# BOSS EAGLE MASTER

## تشغيل التطبيق
- Node.js 18 أو أحدث.
- أمر التشغيل: \`npm start\`.
- فحص الصياغة: \`npm run check\`.
- فحص الصحة: \`GET /health\`.

## إعداد أول حساب MASTER
في إعدادات متغيرات البيئة في الاستضافة، أضف:
- \`MASTER_SETUP_KEY\`: رمز طويل وفريد تختاره أنت (لا تشاركه مع أحد).

بعد إعادة النشر افتح رابط اللوحة، ثم أنشئ حساب MASTER باستخدام رمز التأسيس. يُستخدم الرمز مرة واحدة فقط لإنشاء الحساب الأول.

بدلاً من ذلك يمكن إعداد \`MASTER_USERNAME\` و\`MASTER_PASSWORD\` في متغيرات البيئة قبل أول تشغيل لإنشاء الحساب الرئيسي تلقائياً.

## متغيرات اختيارية
- \`SESSION_SECRET\`: سر جلسات طويل وعشوائي.
- \`PORT\`: يحدده مزود الاستضافة عادةً.

## البيانات
يُنشأ مخزن JSON داخل \`data/master-data.json\`. تأكد من أن مساحة التطبيق دائمة (Persistent Disk/Volume) كي لا تفقد بيانات الحسابات عند إعادة إنشاء الحاوية. لا ترفع مجلد \`data\` إلى GitHub.

## إجراءات الحماية المضافة
- رمز CSRF مرتبط بجلسة المستخدم لكل طلب يغيّر البيانات.
- تدوير معرّف الجلسة بعد إنشاء MASTER أو تسجيل الدخول.
- تحديد محاولات الدخول المتكررة مؤقتاً.
- ترويسات حماية للمتصفح، وإخفاء ترويسة Express.
- فحص تلقائي لصياغة ملفات JavaScript عند كل push إلى GitHub Actions.

ملاحظة: هذه الإجراءات تقلل المخاطر ولا تعني ضمان انعدام جميع الثغرات. لا تستخدم أرصدة أو أموالاً حقيقية قبل اختبار التطبيق كاملاً، وتوفير تخزين دائم وقاعدة بيانات مناسبة للإنتاج.
